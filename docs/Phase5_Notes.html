Project Overview & Tech Stack

Phase 5 builds the financial infrastructure of the SmartRideTIET platform. It implements secure ride-sharing payments via Razorpay (supporting UPI, Credit/Debit cards, Net Banking, and Wallets) and a customizable local prepaid wallet system stored directly in Firebase Firestore. This enables rapid checkouts, especially for campus-internal flat fare (₹10) rides.

💡
Core Objective
Provide a fluid, secure, and instant checkout flow for students. Campus internal rides are flat priced at ₹10 and can be paid immediately using the student's wallet balance, eliminating third-party redirection latency.

Key Concepts Explained

Paise Conversion (Amount Format)

Razorpay processes all currency transactions in the smallest currency unit. For Indian Rupees (INR), the values must be passed in paise. For example, a flat campus fare of ₹10 is passed as 1000 paise. Re-conversion is done by dividing by 100 on retrieval.

HMAC-SHA256 Signature Verification

To prevent malicious students from spoofing success callbacks, the backend validates the signature returned by Razorpay Checkout. We concatenate the order ID and payment ID with a pipe character (order_id|payment_id) and hash it using the merchant Key Secret. If the resulting digest matches the returned signature, the transaction is marked as valid.

Firestore Atomicity via Batches

When a payment is completed, multiple documents must update simultaneously (debiting wallet balance, logging transaction audit trail, changing ride status to paid). We use Firestore db.batch() write batches to ensure all operations succeed or fail together, protecting database consistency.

Dynamic Script Loading

Loading large external checkout SDKs eagerly degrades web performance. We load the Razorpay checkout script (https://checkout.razorpay.com/v1/checkout.js) dynamically in React using a Promise wrapper only when the user clicks the "Pay" button.

Backend Files — Code Explained

1. Razorpay Service

File path: backend/services/razorpay.service.js

Wraps the official Razorpay SDK inside clean, asynchronous helper functions. It retrieves API keys directly from environment configurations.

javascriptconst Razorpay = require('razorpay');
const crypto  = require('crypto');

const razorpay = new Razorpay({
  key_id:     process.env.RAZORPAY_KEY_ID,
  key_secret: process.env.RAZORPAY_KEY_SECRET,
});

const createRazorpayOrder = async (amountInPaise, receipt, notes = {}) => {
  const options = {
    amount:   amountInPaise,
    currency: 'INR',
    receipt,
    notes,
  };
  return await razorpay.orders.create(options);
};

const verifySignature = (orderId, paymentId, signature) => {
  const body = `${orderId}|${paymentId}`;
  const expected = crypto
    .createHmac('sha256', process.env.RAZORPAY_KEY_SECRET)
    .update(body)
    .digest('hex');
  return expected === signature;
};

2. Payment Controller

File path: backend/controllers/payment.controller.js

Provides endpoint controllers for payments. It leverages modular Firestore imports (db and FieldValue) to record payments and perform atomic wallet credits/debits.

javascriptconst { db } = require('../config/firebase');
const { FieldValue } = require('firebase-admin/firestore');
const { createRazorpayOrder, verifySignature, fetchPayment } = require('../services/razorpay.service');

exports.createOrder = async (req, res) => {
  try {
    const { rideId, type = 'ride' } = req.body;
    const userId = req.user.uid;
    let amountInPaise, receipt;

    if (type === 'wallet') {
      const { amount } = req.body;
      amountInPaise = Math.round(amount * 100);
      receipt = `wallet_${userId}_${Date.now()}`;
    } else {
      const rideDoc = await db.collection('rides').doc(rideId).get();
      const ride = rideDoc.data();
      amountInPaise = Math.round(ride.fare * 100);
      receipt = `ride_${rideId}`;
    }

    const order = await createRazorpayOrder(amountInPaise, receipt);
    res.json({ orderId: order.id, amount: order.amount, keyId: process.env.RAZORPAY_KEY_ID });
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
};

Frontend Files — Code Explained

1. Payment Script & Checkout Service

File path: frontend/src/services/paymentService.js

Responsible for dynamically creating a script tag pointing to Razorpay. This keeps index loads clean and prevents errors if external checkout resources are temporarily blocked.

javascriptexport const loadRazorpayScript = () =>
  new Promise((resolve) => {
    if (document.getElementById('razorpay-script')) {
      resolve(true);
      return;
    }
    const script = document.createElement('script');
    script.id = 'razorpay-script';
    script.src = 'https://checkout.razorpay.com/v1/checkout.js';
    script.onload = () => resolve(true);
    script.onerror = () => resolve(false);
    document.body.appendChild(script);
  });

Razorpay Integration Setup — Step by Step

Setup a standard test merchant profile using these steps to test checkout transactions locally without real currency.

  1. Create Account: Go to the Razorpay Dashboard and complete the sign-up. Keep the account in **Test Mode** (indicated by an orange badge at the top menu).

  2. Generate Credentials: Navigate to Settings > API Keys and click Generate Key. Immediately copy both the Key ID and Key Secret to a text document.

  3. Edit Server Environment: Paste the credentials directly into backend/.env under the Razorpay config lines.

  4. Edit Client Environment: Paste the Key ID Only as VITE_RAZORPAY_KEY_ID in frontend/.env. Do not expose your Secret key to the client folder.

  5. Test Credentials: Initiate a transaction. When checkout opens, input success@razorpay as the UPI handle or use card number 4111 1111 1111 1111 with expiry 12/28 and CVV 123.

⚠️
Strict API Hygiene
The Key Secret acts as your private signing certificate. If you accidentally publish it to GitHub or client bundles, anyone can compromise payment confirmations.

Errors & Fixes

During the initialization of Phase 5, these specific blockers arose and were resolved. Review them to prevent runtime crashes.

❌ Error: 'nodemon' is not recognized as an internal or external command
nodemon server.js - command not found
🔧 Fix Applied:

Nodemon was missing from node modules. We executed npm install express cors dotenv firebase-admin razorpay nodemon to install nodemon and the missing backend core files concurrently.

❌ TypeError: admin.firestore is not a function
TypeError: admin.firestore is not a function at Object.<anonymous> (payment.controller.js)
🔧 Fix Applied:

The code was written in legacy Firestore syntax (v9). We replaced the legacy imports with the modular patterns used in config/firebase.js, modifying references to use { db } and { FieldValue } directly.

javascriptconst { db } = require('../config/firebase');
const { FieldValue } = require('firebase-admin/firestore');
✓
Environment Variables Load Order
Remember to stop and restart the terminal tasks (npm run dev) after adding API keys to .env files. Dev tools do not hot-reload system variables dynamically.
